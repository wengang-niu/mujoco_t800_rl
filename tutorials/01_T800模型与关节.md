## 1.1 本章目标

本章不急着控制机器人，而是先回答四个问题：

1. T800 有哪些关节，它们的顺序和含义是什么？
2. `body`、`joint`、`geom`、`site`、`actuator`、`sensor` 分别做什么？
3. 如何从 MuJoCo 查询关节状态地址，而不是硬编码数组切片？
4. 关节和执行器怎样一一对应？

## 1.3 MJCF 文件如何组成 T800

入口文件 [models/t800/t800.xml](../models/t800/t800.xml) 很短，主要包含：

```xml
<mujoco model="global_model">
    <include file="robot/t800/xml/serial_t800.xml"/>
    <include file="environment/ground.xml"/>
</mujoco>
```

继续沿 include 查找，会看到：

- `serial_t800.xml`：编译选项、默认参数、自由基座和机器人主体；
- `serial_links.xml`：各连杆和关节的树状结构；
- `serial_actuators.xml`：25 个 motor actuator；
- `serial_sensors.xml`：基座、IMU 和双脚力/力矩传感器；
- `assets.xml`：网格和材质；
- `ground.xml`：地面、光照和接触环境。

### 六个容易混淆的对象

| 对象 | 含义 | T800 示例 |
|---|---|---|
| `body` | 刚体/连杆，形成运动学树 | `LINK_BASE`、大腿、足部 |
| `joint` | 两个刚体之间允许的相对运动 | `J03_KNEE_PITCH_L` |
| `geom` | 可视或碰撞几何体 | 脚底碰撞盒、外观网格 |
| `site` | 无质量的参考点/坐标系 | `imu`、脚部力传感器位置 |
| `actuator` | 对 joint 施加控制输入 | `motor_J03_KNEE_PITCH_L` |
| `sensor` | 输出模拟测量值 | gyro、accelerometer、force |

`joint` 不是电机；`actuator` 才接收 `data.ctrl`。一个关节可以没有执行器，也可以在更复杂模型中由不同传动机构驱动。

## 1.4 T800 的 25 个驱动关节

SDK 在 [assets/config/t800/model/default.yaml](../engineai_robotics_native_sdk/assets/config/t800/model/default.yaml) 中给出规范分组：

| 索引 | 关节 | 部位 |
|---:|---|---|
| 00–05 | `J00_HIP_PITCH_L` … `J05_ANKLE_ROLL_L` | 左腿 |
| 06–11 | `J06_HIP_PITCH_R` … `J11_ANKLE_ROLL_R` | 右腿 |
| 12 | `J12_TORSO_YAW` | 腰部 |
| 13–17 | `J13_SHOULDER_PITCH_L` … `J17_ELBOW_YAW_L` | 左臂 |
| 18–22 | `J18_SHOULDER_PITCH_R` … `J22_ELBOW_YAW_R` | 右臂 |
| 23–24 | `J23_HEAD_PITCH`、`J24_HEAD_YAW` | 头部 |

完整规范顺序如下：

```text
J00_HIP_PITCH_L
J01_HIP_ROLL_L
J02_HIP_YAW_L
J03_KNEE_PITCH_L
J04_ANKLE_PITCH_L
J05_ANKLE_ROLL_L
J06_HIP_PITCH_R
J07_HIP_ROLL_R
J08_HIP_YAW_R
J09_KNEE_PITCH_R
J10_ANKLE_PITCH_R
J11_ANKLE_ROLL_R
J12_TORSO_YAW
J13_SHOULDER_PITCH_L
J14_SHOULDER_ROLL_L
J15_SHOULDER_YAW_L
J16_ELBOW_PITCH_L
J17_ELBOW_YAW_L
J18_SHOULDER_PITCH_R
J19_SHOULDER_ROLL_R
J20_SHOULDER_YAW_R

J22_ELBOW_YAW_R
J23_HEAD_PITCH
J24_HEAD_YAW
```

名称前缀 `J00`–`J24` 正好表达全身向量索引，但程序仍应按名称验证，不要只相信文件顺序。

## 1.5 完整程序：检查 joint、actuator 和 sensor

将下面代码复制为 `/tmp/lesson01_inspect_t800.py`，并从仓库根目录运行。

```python
from pathlib import Path

import mujoco
import numpy as np


MODEL_PATH = Path("models/t800/t800.xml").resolve()

JOINT_GROUPS = {
    "left_leg": [
        "J00_HIP_PITCH_L", "J01_HIP_ROLL_L", "J02_HIP_YAW_L",
        "J03_KNEE_PITCH_L", "J04_ANKLE_PITCH_L", "J05_ANKLE_ROLL_L",
    ],
    "right_leg": [
        "J06_HIP_PITCH_R", "J07_HIP_ROLL_R", "J08_HIP_YAW_R",
        "J09_KNEE_PITCH_R", "J10_ANKLE_PITCH_R", "J11_ANKLE_ROLL_R",
    ],
    "waist": ["J12_TORSO_YAW"],
    "left_arm": [
        "J13_SHOULDER_PITCH_L", "J14_SHOULDER_ROLL_L",
        "J15_SHOULDER_YAW_L", "J16_ELBOW_PITCH_L", "J17_ELBOW_YAW_L",
    ],
    "right_arm": [
        "J18_SHOULDER_PITCH_R", "J19_SHOULDER_ROLL_R",
        "J20_SHOULDER_YAW_R", "J21_ELBOW_PITCH_R", "J22_ELBOW_YAW_R",
    ],
    "head": ["J23_HEAD_PITCH", "J24_HEAD_YAW"],
}
JOINT_NAMES = [name for group in JOINT_GROUPS.values() for name in group]

JOINT_TYPE_NAMES = {
    int(mujoco.mjtJoint.mjJNT_FREE): "free",
    int(mujoco.mjtJoint.mjJNT_BALL): "ball",
    int(mujoco.mjtJoint.mjJNT_SLIDE): "slide",
    int(mujoco.mjtJoint.mjJNT_HINGE): "hinge",
}


def object_name(model: mujoco.MjModel, obj_type: mujoco.mjtObj, obj_id: int) -> str:
    name = mujoco.mj_id2name(model, obj_type, obj_id)
    return name if name is not None else f"<unnamed:{obj_id}>"


def main() -> None:
    model = mujoco.MjModel.from_xml_path(str(MODEL_PATH))
    data = mujoco.MjData(model)
    mujoco.mj_forward(model, data)

    print("=== model dimensions ===")
    print(
        f"nbody={model.nbody}, njnt={model.njnt}, "
        f"nq={model.nq}, nv={model.nv}, nu={model.nu}, nsensor={model.nsensor}"
    )

    if model.nu != len(JOINT_NAMES):
        raise ValueError(f"期望 {len(JOINT_NAMES)} 个执行器，实际为 {model.nu}")

    print("\n=== free base ===")
    for joint_id in range(model.njnt):
        joint_type = int(model.jnt_type[joint_id])
        if joint_type == int(mujoco.mjtJoint.mjJNT_FREE):
            print(
                f"joint_id={joint_id}, "
                f"name={object_name(model, mujoco.mjtObj.mjOBJ_JOINT, joint_id)}, "
                f"qpos_adr={model.jnt_qposadr[joint_id]}, "
                f"qvel_adr={model.jnt_dofadr[joint_id]}"
            )

    print("\n=== actuated joints ===")
    header = (
        "idx group       joint_name                  type   qadr dadr "
        "axis                 range(rad)       actuator ctrlrange(Nm)"
    )
    print(header)
    print("-" * len(header))

    joint_to_group = {
        joint_name: group
        for group, joint_names in JOINT_GROUPS.items()
        for joint_name in joint_names
    }

    for expected_index, joint_name in enumerate(JOINT_NAMES):
        joint_id = mujoco.mj_name2id(model, mujoco.mjtObj.mjOBJ_JOINT, joint_name)
        if joint_id < 0:
            raise KeyError(f"模型中缺少关节 {joint_name}")

        actuator_name = f"motor_{joint_name}"
        actuator_id = mujoco.mj_name2id(
            model, mujoco.mjtObj.mjOBJ_ACTUATOR, actuator_name
        )
        if actuator_id < 0:
            raise KeyError(f"模型中缺少执行器 {actuator_name}")

        # actuator_trnid[:, 0] 是该 actuator 传动目标的 joint id。
        transmitted_joint_id = int(model.actuator_trnid[actuator_id, 0])
        if transmitted_joint_id != joint_id:
            raise ValueError(f"{actuator_name} 没有驱动 {joint_name}")

        joint_type = int(model.jnt_type[joint_id])
        qpos_adr = int(model.jnt_qposadr[joint_id])
        qvel_adr = int(model.jnt_dofadr[joint_id])
        axis = model.jnt_axis[joint_id]
        joint_range = model.jnt_range[joint_id]
        ctrl_range = model.actuator_ctrlrange[actuator_id]

        print(
            f"{expected_index:>3} {joint_to_group[joint_name]:<11} "
            f"{joint_name:<27} {JOINT_TYPE_NAMES[joint_type]:<6} "
            f"{qpos_adr:>4} {qvel_adr:>4} "
            f"{np.array2string(axis, precision=1):<20} "
            f"[{joint_range[0]:>6.3f}, {joint_range[1]:>6.3f}] "
            f"{actuator_name:<33} "
            f"[{ctrl_range[0]:>6.1f}, {ctrl_range[1]:>6.1f}]"
        )

    print("\n=== named sensors ===")
    for sensor_name in (
        "base_link_quaternion",
        "base_link_position",
        "imu_quaternion",
        "imu_linear_acceleration",
        "imu_angular_velocity",
        "force_left_foot",
        "torque_left_foot",
        "force_right_foot",
        "torque_right_foot",
    ):
        sensor_id = mujoco.mj_name2id(
            model, mujoco.mjtObj.mjOBJ_SENSOR, sensor_name
        )
        if sensor_id < 0:
            raise KeyError(f"模型中缺少传感器 {sensor_name}")
        adr = int(model.sensor_adr[sensor_id])
        dim = int(model.sensor_dim[sensor_id])
        value = data.sensordata[adr : adr + dim].copy()
        print(
            f"{sensor_name:<28} id={sensor_id:>2} "
            f"adr={adr:>2} dim={dim} value={value}"
        )

    print("\n检查通过：25 个规范关节均存在，并各自对应一个 actuator。")


if __name__ == "__main__":
    main()
```

运行：

```bash
python /tmp/lesson01_inspect_t800.py
```

## 1.6 如何正确读取某个关节状态

对 hinge joint：

```python
joint_id = mujoco.mj_name2id(
    model, mujoco.mjtObj.mjOBJ_JOINT, "J03_KNEE_PITCH_L"
)
qpos_adr = model.jnt_qposadr[joint_id]
qvel_adr = model.jnt_dofadr[joint_id]
q = data.qpos[qpos_adr]
qd = data.qvel[qvel_adr]
```

这种方式比直接写 `data.qpos[10]` 更可靠，因为它表达了语义，也不会把自由基座偏移散落在代码中。

> 对 free joint 或 ball joint，位置和速度都不是单个标量。上面的标量读取方式专用于本模型的 25 个 hinge joint。

## 1.7 执行器上限不是推荐教学力矩

[serial_actuators.xml](../engineai_robotics_native_sdk/assets/resource/robot/t800/xml/serial_actuators.xml) 中的 `ctrlrange` 很大，例如部分髋关节和膝关节达到数百 N·m。这是模型硬限制，不表示初学实验应该直接使用该数值。

后续课程会采用两层限制：

1. 教学用保守上限；
2. MJCF `ctrlrange` 硬上限。

控制值必须同时满足两者。

## 1.8 Sensor 地址和顺序

`sensordata` 是一个扁平数组。`model.sensor_adr[sensor_id]` 给出起点，`model.sensor_dim[sensor_id]` 给出维度。

本课程尽量按 sensor 名称查询。SDK 的 C++ 仿真器为了效率按照固定顺序解析，因此 [serial_sensors.xml](../models/t800/robot/t800/xml/serial_sensors.xml) 明确警告：如果改变 sensor 顺序，就必须同步修改 SDK `main.cc`。不要为了教程重排原模型传感器。

## 1.9 预期结果

运行检查程序后应满足：

- 25 个规范 joint 都能找到；
- 每个 joint 都有 `motor_<joint_name>` actuator；
- actuator 的传动目标 joint 正确；
- 所有驱动 joint 类型均为 `hinge`；
- base、IMU、左右脚 force/torque sensor 均能按名称找到；
- actuator ID 通常与 J00–J24 顺序一致，但程序仍进行了显式验证。

## 1.10 常见错误

### 把 joint ID 当作 qpos 地址

`joint_id` 是 joint 表中的编号，`jnt_qposadr` 才是它在 `data.qpos` 中的起始地址。自由基座存在时，两者通常不同。

### 把 `qpos` 与角度自由度一一对应

四元数使用 4 个 `qpos` 数，但只有 3 个旋转自由度。因此不能假设 `len(qpos) == len(qvel)`。

### 把 `ctrlrange` 当作关节角范围

- `jnt_range`：关节位置范围，单位对 hinge 来说是 rad；
- `actuator_ctrlrange`：执行器输入范围，本模型 motor 的输入可视为 N·m。

### 根据 sensor 扁平数组位置猜含义

优先用 sensor 名称查询 `sensor_adr` 和 `sensor_dim`。SDK 的位置解析依赖 XML 顺序，修改模型前必须理解这个约束。

## 1.11 安全提示

- 本章只读取模型，不需要施加大力矩。
- 不要将 MJCF 的最大 `ctrlrange` 直接复制到真机命令中。
- 不要修改原始 joint/actuator/sensor 顺序；后续代码和 SDK 可能依赖该契约。
- 任何关节映射不一致都应立即报错，而不是“尽量继续运行”。

## 1.14 与原生 SDK 的关系

本章的 `JOINT_GROUPS` 对照 SDK 的 [model/default.yaml](../engineai_robotics_native_sdk/assets/config/t800/model/default.yaml)；actuator 名称和上限对照 [serial_actuators.xml](../engineai_robotics_native_sdk/assets/resource/robot/t800/xml/serial_actuators.xml)。SDK 控制向量依赖这套顺序。后续 RL 策略只控制部分关节时，也必须显式建立 active-joint 到全身关节的映射。
